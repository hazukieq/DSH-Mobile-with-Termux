# 证据纪律（强制清单）

> 用户明确要求：这组规则违反即返工，优先级高于默认习惯。
> 加载后**逐条执行**，并如实报告哪一条救了场 / 哪一条被违反。

## 一、回执与证据

1. **先读完再引用**：任何回执先看原始 JSON/文本形态，再解析。解析结果为空 → **先怀疑自己的解析或管道**，不得当成「无变化 / 无证据」。
2. **断言分级**：交付物（issue／文档／汇报／分享内容）里每条断言标注 **【已证实】**（可复现回执或文档条款）或 **【推测】**。推测可以不写；写了必须标明。
3. **单变量不外推**：一次实验只支持它测的那个变量。「脚本 `location.href` 没 handoff」≠「App 拦截外部导航」；「点一下没反应」≠「通道坏了」。
4. **回执字段是诊断不是真相**：`window.target` / `window.all` / `ownOverlay` 只描述落点窗口（`docs/ACCESSIBILITY.md` §9.2）。手势是否生效应看 `scr changed` / 目标文本 / `checked`。`ok:true` 只代表已派发。

## 二、先文档后实验

5. **先读文档**：涉及「点击 / 前台窗口 / handoff / 无障碍」判断前，先读
   - `$DSH_HOME/docs/ACCESSIBILITY.md`（§8 ownOverlay、§9 坐标 tap 语义、§11 回执纪律）
   - `$DSH_HOME/docs/CLICK_CHAIN_UPGRADE.md`（点击链路与失败重试）
   - `$DSH_HOME/DSH-MOBILE.md`（「Hand-off semantics」等）
   文档能回答 → **不要做实验**。
6. **用户断言按强证据处理**：用户说「shouldOverrideUrlLoading 生效」「handoff 是通的」「那个是这么回事」→ 先接受并据此修正，禁止在未读文档的情况下反驳或继续自证。
7. **收到「读文档 / 别测了」立即停手**：停止实验，读文档，复述要点，再谈方案。

## 三、实验纪律

8. **文档答不了才测**：一次只测一个变量；测前声明「验证什么 / 判据是什么」；测完先看回执再看结论。
9. **清场与恢复**：排除干扰窗口（含残留的其他 App 窗口）、移除注入元素、回到前台。`force-stop` 别的 App、注入浮层这类影响用户现场的动作，先说明再做。
10. **测试元素设计**：注入的可点目标必须**整块可点**（不要外套整屏 `div` 再点中间的小 `<a>`）；判定用目标状态（`scr changed` / 文本出现），不用点击回执的窗口字段。

## 四、交付与 handoff

11. **handoff 是终态**：`handoff:true` / `stop:true` / `verify:"none"` → 不重试、不截图、不轮询、不反推「没生效」。
12. **分享/发布前自检**：有没有【推测】被写成事实？有没有引用自己没读过的回执？有则删除或标注。

## 五、交付前 30 秒自检（逐项答是/否）

- [ ] 我是否原样读过每一条被引用的回执？
- [ ] 每个断言都标了【已证实】/【推测】？
- [ ] 有没有把「一次实验」外推成「机制结论」？
- [ ] 有没有用 `window.target` 之类诊断字段当因果？
- [ ] 结论涉及的机制，文档里查过吗？引用了哪一条？
- [ ] 用户已经说过的结论，我是否接受并复述了？
- [ ] 现场恢复了吗（注入元素、前台、其他 App）？

## 六、本会话真实反例（记住这些形状）

1. `/screen` 返回 `fg=…` 文本，却用 grep 找 JSON `"foreground"` → 14 行空结果，差点当「无变化」。（规则 1）
2. 脚本 `location.href` 无 handoff → 写成「App 拦截外部导航」，并写进已分享的 issue。（规则 3、2）
3. `window.target=com.microsoft.emmx` → 断定「点进了 Edge 窗口」。（规则 4）
4. 注入整屏 `div` 套小 `<a>`，点 (540,1200) 大概率落在 div 上；环境里还有 Edge 窗口残留 → 测试无效。（规则 10、9）
5. 用户两次说「可以跳转外部，handoff 而已」，仍继续自证。（规则 6）
6. 文档已覆盖的判断上反复做实验，被用户喝止「测个 p」。（规则 5、7）
7. 错误结论先发到 QQ，再返工两次。（规则 2、12）
8. 拿到 `handoff:true` 后还反推「没生效」。（规则 11）

## 七、输出模板（写 issue / 汇报时）

```markdown
## 结论
- 【已证实】…（依据：<回执字段/文档条款>）
- 【推测】…（依据：<为什么这么猜>；待验证：<怎么验>）
```

不确定就写「未验证」，**不要**用肯定语气填空。

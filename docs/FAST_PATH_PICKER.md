# Fast-Path Picker：端侧本地决策的 UI 自动化加速层

> 把「该点屏幕上的哪个元素」从云端大模型（秒级）搬到设备本地（毫秒~百毫秒级），且本地模型不需要看图、
> 不需要输出坐标。

GUI Agent 单步常要 2–5 秒，其中大部分步骤只在回答一个很窄的问题：「屏幕上这几个文本里，哪个是用户要点的
那个？」——这正是本地小模型能接住的部分。

## 设计：三层递进，越快的越先命中

```
目标描述（如「打开 WLAN」）
  ├─ ① 精确/子串匹配 ───────────────────────── 1-2 ms   无需模型
  │    节点文本 == 目标 / 包含 / 被包含
  ├─ ② 本地语义匹配 ────────────────────────── ~93 ms   无网络往返
  │    bge-small-zh（15MB, 24M 参数, 512 维）：目标向量 vs 各节点文本向量 → 余弦相似度取最高；
  │    阈值 0.62，低于阈值宁可降级也不瞎点
  └─ ③ 云端兜底 ───────────────────────────── 2-5 s
       把候选列表（含文本与坐标）一并返回，大模型在**一轮内**做出选择（不必反复 dump）
```

### 为什么本地模型可以「极小」

三条约束的撤销，让 15MB 的模型就够用：

1. **不看图** —— 输入是屏幕文本节点，不是截屏 → 不需要多模态模型
2. **不输出坐标** —— 坐标由无障碍层从节点直接取（点文本节点中心，事件冒泡到可点击祖先，与 `tap-text`
   同一原理）→ 不需要生成式解码
3. **只做排序** —— 「哪个最相关」本质是检索问题 → **嵌入模型**比生成模型快一个量级（一次前向 vs 逐 token
   解码）

## 延迟与体积（emulator-5554，llama-server 0.6.0，bge-small-zh-v1.5-q4_k_m）

| 层 | 延迟 | 命中样例 |
|---|---|---|
| ① 精确 | **1-2 ms** | `网络和互联网`→该节点 @(369,712)；`WLAN`→`移动网络、WLAN、热点` |
| ② 语义 | **85-102 ms（均 92.7）** | `打开 WLAN`→`移动网络、WLAN、热点`，cos **0.670** |
| ② 对照 | — | `铃声和振动` cos **0.333**（区分度足够） |
| 首次（预热） | 247 ms | 仅一次 |
| 模型体积 | **15.4 MB** | gguf q4_k_m，512 维 |

本地语义层依赖 Termux 扩展 `llama-cpp`（提供 `llama-server`），安装约 15 秒。

## 实现要点

1. **紧凑 dump 里"可点击的容器文本是 `-`"** —— 真正文本在子节点上而无 `c` 标记。若按 clickable 过滤，候选
   全是 `-`，永远选不中。**候选 = 有文本的节点，clickable 只用于同分排序。**
2. **模型只能是加速器，不能是依赖** —— 没装扩展/没下模型/服务没起时，第 ② 层返回 null，第 ③ 层接住；
   任何情况下用户不被阻塞。
3. **下载写到 `.part` 再改名** —— 半截文件不能当成完整模型；**`llama-server` 的 `-t 2`** —— 别把引擎和 UI
   的核全占了，`-c 512` 足够放「目标 + ~10 个屏幕文本」。
4. **WebUI 的桥 token 与 engine.log 里的 WebUI token 不是同一个** —— 调桥要用 `DSH_BRIDGE_TOKEN`（引擎
   子进程环境里）。

## 接口与代码位置

| 文件 | 职责 |
|---|---|
| `engine/FastPicker.kt` | 三层选择逻辑 + 紧凑 dump 解析 |
| `engine/FastPicker.kt`（`object LocalEmbedder`，:202 起） | 嵌入服务客户端（/v1/embeddings + 余弦） |
| `engine/LocalModel.kt` | 模型下载（多镜像 failover）+ llama-server 生命周期 |
| `engine/AgentBridge.kt` | `POST /pick`、`GET /local/status`、`POST /local/ensure` |
| `assets/gates/scr` | `scr pick <目标> [--tap] [--all]` |
| `pkg install llama-cpp` | 提供 `llama-server`（本地语义层可选依赖） |
| `scripts/probes/test_pick.py`、`test_embed.mjs` | pick 三层命中测试、嵌入延迟与命中率测量 |

## 现状

`POST /pick`、`GET /local/status`、`POST /local/ensure` 与 `scr pick` 均可用；精确层与本地嵌入层在真机
（arm64）验证通过，语义层依赖可选的 `pkg install llama-cpp`。未命中任何一层时回落到云端决策，关掉本地模型也不影响功能。
